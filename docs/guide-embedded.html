Embedded Deployment

Deploying Axiom models on resource-constrained devices, from Raspberry Pi to bare-metal Cortex-M.

The Idea

Train on a big machine with the full Axiom library. Save the model. Deploy to the target with an inference-only build that strips everything training-related. The result is a tiny, self-contained binary that loads the model and runs forward passes.

Inference-Only Build

The AX_INFERENCE_ONLY flag strips autograd, optimizers, losses, backward passes, and all training-related code:

cmake -DCMAKE_BUILD_TYPE=MinSizeRel \
      -DAX_INFERENCE_ONLY=ON ..

This produces a library that supports:

  • Tensor creation and manipulation
  • ax_layer_forward() / ax_model_predict()
  • ax_model_load()
  • All compute backends (naive, SIMD)

It does NOT include:

  • ax_backward(), ax_optimizer_step(), any loss functions
  • Gradient tracking, grad_fn allocation, computation graph
  • Data loading (datasets, dataloaders)

ax_grad_enabled() always returns false. Any code that calls training-only functions will get a link error, which is the clearest signal that this build does not support training.

Build Profiles

Embedded Linux

For devices running Linux (Raspberry Pi, Jetson Nano, BeagleBone):

cmake -DCMAKE_BUILD_TYPE=Release \
      -DAX_PROFILE=embedded-linux \
      -DAX_INFERENCE_ONLY=ON ..

This reduces internal buffer sizes and trims features not needed on edge devices, while still using the full standard library.

Bare-Metal

For microcontrollers with no OS (Cortex-M, RISC-V):

cmake -DCMAKE_BUILD_TYPE=MinSizeRel \
      -DAX_PROFILE=embedded-baremetal \
      -DAX_INFERENCE_ONLY=ON \
      -DCMAKE_TOOLCHAIN_FILE=your-cortexm-toolchain.cmake ..

This disables:

  • stdio (no printf, no file I/O)
  • Dynamic allocation (no malloc/free)
  • Threads (no pthreads, no OpenMP)

You provide memory through pre-allocated buffers. Tensor storage points into your static arrays.

Workflow

  1. Train on a workstation using the full Axiom library. Save with ax_model_save(m, "model.axm").
  2. Cross-compile the inference-only library for your target.
  3. Load and run on the target:
#include "axiom/axiom.h"

int main(void) {
    ax_init();

    // load the trained model
    ax_model_t *m = ax_model_load("model.axm");
    if (!m) {
        // handle error
        return 1;
    }

    // prepare input (e.g., from sensor data)
    float sensor_data[784];
    // ... read from ADC, camera, etc.

    ax_tensor_t *input = ax_tensor_from_array(
        sensor_data, (int64_t[]){1, 784}, 2, AX_FLOAT32);

    // run inference
    ax_tensor_t *output = ax_model_predict(m, input);

    // read the result
    float prediction = ax_tensor_get_f32(output, (int64_t[]){0, 0});

    ax_tensor_destroy(output);
    ax_tensor_destroy(input);
    ax_model_destroy(m);
    ax_shutdown();
    return 0;
}

Binary Size

With AX_INFERENCE_ONLY=ON and -Os or MinSizeRel:

TargetBinary Size
ARM aarch64 (Linux)< 100KB
ARM Cortex-M (bare-metal)~40-60KB (depends on layers used)
x86_64 (Linux)~120KB

The linker strips unused layer types. If your model only uses Dense and ReLU, Conv2D code is not linked in.

Memory Considerations

  • Model weights are the biggest consumer. A 1.46M parameter model needs ~5.6MB of float32 storage. Consider smaller architectures for very constrained targets.
  • Activations (intermediate tensors during forward pass) need memory proportional to the largest layer's output. This is allocated and freed during inference.
  • No gradient memory. Inference-only builds never allocate gradient tensors, saving roughly 2x the parameter memory compared to training.
  • Arena allocator is used for temporary compute buffers. Its memory is reused across calls without repeated malloc/free.

NEON on ARM

On aarch64, Axiom automatically uses NEON SIMD instructions for GEMM (8x12 micro-kernel) and element-wise ops. No special flags needed. The NEON backend is compiled in by default for ARM targets.

Model Format

The .axm binary format is designed for embedded:

  • No external dependencies (no protobuf, no JSON)
  • Fixed-size header, simple structure
  • Little-endian throughout
  • Can be read incrementally (no need to load the entire file at once)
  • Magic bytes: 0x41584F4E ("AXON")
