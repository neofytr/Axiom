
# axiom

pure C deep learning framework. zero external dependencies. trains and serves
neural networks from cloud servers down to cortex-m microcontrollers.

## build

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j$(nproc)
ctest --test-dir build --output-on-failure
```

key cmake flags:
- `-DAX_CUDA=ON` enables NVIDIA GPU backend (requires CUDA toolkit)
- `-DAX_PROFILE=embedded-linux` or `embedded-baremetal` for embedded targets
- `-DAX_SANITIZE=ON` for ASAN+UBSAN (debug builds only)
- `-DAX_TSAN=ON` for thread sanitizer
- `-DAX_INFERENCE_ONLY=ON` strips training code (<100 KB binary)
- `-DAX_NO_AUTOTUNE=ON` skips startup calibration (faster launch, embedded)
- `-DAX_SINGLE_THREADED=ON` disables all OpenMP
- `AX_GEMM_CALIBRATE=0` env var skips GEMM tile calibration at runtime

## architecture

```
include/axiom/          25 public headers (stable ABI, SemVer)
include/axiom/internal/ 5 internal headers (no ABI promise)
src/core/               tensor, ops, autograd, layers, training infra
src/core/conv/          9 files: forward, backward, im2col, winograd, direct, autotune, pool, cbr fusion, path selection
src/core/attention/     5 files: layout, cache, train_step variants (v1/fused/v4)
src/compute/            dispatch.c (backend routing), calib_cache.c
src/compute/backends/   cpu_naive.c, cpu_opt.c (9.4K LOC), JIT (x64+arm64), CUDA (10 .cu files)
tests/                  34 test files
benchmarks/             23 C benchmarks + python TF comparison scripts
examples/               5 runnable examples (xor, spiral, mnist, mnist_cnn, deep_mlp)
```

the compute layer uses a vtable dispatch: cpu_naive (scalar fallback) -> cpu_opt
(SIMD tiled GEMM with JIT micro-kernels) -> CUDA (cuBLAS + custom fused kernels).
ISA is detected at runtime (AVX-512 > AVX2 > NEON > scalar).

## naming conventions

- public symbols: `ax_` prefix. enum values: `AX_`.
- verbs: create/destroy/get/set/forward/backward.
- types.h has version constants (AX_VERSION_MAJOR/MINOR/PATCH).
- internal headers under `axiom/internal/` are not installed.

## code style

- C11. lowercase succinct comments only. no multi-line comment blocks.
- no `---` dash separators in comments.
- no AI attribution (Co-Authored-By, "generated by", etc.) in commits or code.
- when adding new ops/layers: write tests first, then implement.

## performance philosophy

this is the single most important aspect of the framework. every optimization
must be GENERAL, not machine-specific. use runtime detection, calibration
caches, and autotuners for all thresholds and tile sizes. the framework must
perform well on any hardware from embedded ARM to server x86.

key performance files:
- `src/compute/backends/cpu_opt.c` (9.4K LOC) — BLIS-style 5-loop tiled GEMM,
  JIT micro-kernels (14x32 AVX-512, 6x16 AVX2, NEON). this is the hottest
  file. changes here require running the full benchmark suite.
- `src/compute/dispatch.c` — thread-local GEMM flags (skip_init, inner_team),
  OMP threshold calibration, backend routing.
- `src/core/conv/` — six conv paths (winograd, direct 3x3, smallcin, implicit
  GEMM, im2col, batched). autotuner trials all eligible paths per shape.
- `src/core/attention/train_step_v4.c` — latest MHA training kernel with
  FlashAttention-style tiling.

GEMM tile parameters (auto-calibrated at startup):
- MC, NC, KC sized to fit L1d/L2/L3 caches detected at runtime
- MR=14, NR=32 on AVX-512; MR=6, NR=16 on AVX2; MR=8, NR=12 on NEON
- thread-local `ax_gemm_inner_team` flag for worksharing inside existing
  OMP regions (avoids nested parallel region overhead)
- thread-local `ax_gemm_skip_init` flag for accumulating into existing
  buffers without zeroing

## conv backward architecture

the conv backward (src/core/conv/backward.c) is currently the weakest
performance area. the pipeline per sample is:
1. im2col: gather input patches into [K, M] matrix
2. dW: GEMM_NT(grad_out, col) -> weight gradient [C_out, K]
3. dX: GEMM_TN(weight, grad_out) -> dcol [K, M], then col2im -> input gradient
4. db: parallel channel-sum of grad_out

three dispatch paths:
- N==1: single-threaded outer loop, inner GEMM/im2col uses full thread team
- 1 < N < T: inner_team mode, full thread team cooperates on each sample sequentially
- N >= T: per-sample parallel with per-thread dW buffers, parallel reduction

known bottleneck: dW GEMM has M=C_out which is often small (64-256), giving
poor tile utilization (2-6 MC tiles for 16 threads). this is the primary
reason conv backward is 3-5x slower than TF+MKL.

## winograd F(2,3)

winograd.c handles 3x3 stride=1 pad=1 convolutions. forward only (no backward
path yet). eligibility: K=3x3, S=1, P=1, C_in>=32, C_out>=32, out>=4x4, V buffer
< 32 MB. the autotuner trials winograd against im2col and picks the winner.

currently winograd forward is ~4.5x slower than im2col due to: cache-thrashing V/M
scatter, 16 sequential GEMM calls each creating OMP regions, scalar transforms.

## testing

every module has a corresponding test file. run all tests:
```bash
cd build && ctest --output-on-failure
```

for fast iteration (skip calibration):
```bash
AX_NO_AUTOTUNE=1 AX_GEMM_CALIBRATE=0 ./build/test_conv
```

## benchmarking

the comprehensive benchmark covers 77 datapoints across 7 categories
(GEMM NN/TN, conv fwd+bwd, batchnorm, MLP, MHA, softmax, relu).

```bash
# build
cd build && cmake .. -DCMAKE_BUILD_TYPE=Release && make -j$(nproc)

# run axiom benchmark
AX_GEMM_CALIBRATE=0 ./bench_comprehensive

# run TF comparison (must run sequentially, not concurrently with axiom)
cd ../benchmarks && python3 bench_comprehensive_tf.py > /tmp/tf_results.txt
```

always run axiom and TF benchmarks SEQUENTIALLY to avoid CPU contention.
use `AX_GEMM_CALIBRATE=0` to skip calibration overhead in benchmarks (the
calibration cache persists from previous runs).

## current benchmark status

axiom wins 54/77 (70%) vs TF+MKL. per-category:
- GEMM NN: 15/18, GEMM TN: 17/18, MLP: 5/5, ReLU: 4/4 (strong)
- BN: 4/6, Softmax: 4/6, MHA: 3/8 (mixed)
- Conv: 2/12 (weak, backward is the bottleneck)

## embedded targets

three build profiles in cmake/profiles/:
- `desktop`: full training, OpenMP, autotuning (default)
- `embedded-linux`: training enabled, no autotuner, reduced buffers
- `embedded-baremetal`: inference-only, no threads, no stdio, no heap

the framework is designed to run well on embedded/edge devices with
minimal memory. W8A32 int8 quantization is available for inference.

## key env vars

- `OMP_NUM_THREADS=N` — control thread count
- `AX_GEMM_CALIBRATE=0` — skip GEMM tile calibration
- `AX_NO_AUTOTUNE=1` — skip conv path autotuning
- `AX_SDPA_FUSED=1` — enable FlashAttention-2 fused variant

## serialization

models save/load via `.axm` binary format (little-endian, portable).
magic: 0x41584F4E ("AXON"), format version 4.

## what NOT to do

- never add external dependencies (no BLAS, no protobuf, no python runtime)
- never add machine-specific tuning (no hardcoded tile sizes for "my laptop")
- never skip tests when modifying core ops
- never modify cpu_opt.c GEMM micro-kernels without running full benchmarks
- never use `---` dash separators in comments
- never add AI attribution to commits or code
