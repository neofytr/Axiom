1. WHAT IS AXIOM
================================================================================

Axiom is a deep learning framework written from scratch in pure C. It started
as a simple header-only neural network library called neoNN (built ~early 2025)
and is being evolved into a fully-featured, production-grade framework.

The primary differentiator is the embedded/edge deployment niche:
- Zero external dependencies (no Python, no protobuf, no BLAS required)
- Compiles to a single .a or .so file
- Runs on microcontrollers, Raspberry Pi, IoT devices
- Small binary footprint, minimal memory allocation during inference
- Fixed-size arrays where possible (configurable at compile time)

But it also works as a general-purpose desktop framework:
- Full training support with autograd
- Modern optimizers (Adam, AdamW, etc.)
- CNN support with im2col
- Model save/load in a portable binary format
- Data pipeline with batching, shuffling, transforms


================================================================================
2. ARCHITECTURE
================================================================================

The architecture is layered. Dependencies flow downward only.

    User Code
        |
    Model API          (model.h, model.c)
        |
    Layer Library      (layer.h, layer.c, conv.c, norm.c)
        |
    Training Engine    (optim.h, losses.h, lr_scheduler.h)
        |
    Autograd Engine    (autograd.h, autograd.c, autograd_ops.c)
        |
    Tensor API         (tensor.h, tensor.c, ops.h, ops.c)
        |
    Compute Dispatch   (compute.h, dispatch.c, backend_ops.h)
        |
    CPU Backend        (cpu_naive.c)  [future: SIMD, CUDA]
        |
    Memory Management  (memory.h, memory.c)
        |
    Core Utilities     (types.h, error.h, error.c)

Key design: the compute backend is a vtable (function pointer table). Every
math operation routes through ax_compute_*() which calls the active backend.
Swapping CPU for GPU means registering a new vtable — nothing above changes.

4. WHAT HAS BEEN BUILT (PHASES 0-7 + HARDENING)
================================================================================

Phase 0: Foundation
  - Types, error handling, arena allocator, aligned alloc
  - CMake build system with sanitizer support

Phase 1-2: Tensor Engine + Autograd
  - N-dimensional tensors with stride support
  - Ref-counted storage, zero-copy reshape/transpose
  - Broadcasting (numpy rules)
  - Reverse-mode automatic differentiation
  - Backward functions for: add, sub, mul, div, neg, exp, log, sqrt,
    square, matmul, sum, mean, relu, sigmoid, tanh, scalar ops

Phase 3: Training Toolkit
  - Activations: leaky relu, elu, selu, gelu, swish, softplus, mish, softmax
  - Losses: mse, mae, cross-entropy, binary cross-entropy, huber
  - Optimizers: sgd (momentum, nesterov), adam, adamw, rmsprop, adagrad
  - Weight init: xavier, kaiming, lecun (uniform + normal), constant/zeros/ones

Phase 4: Layer System + Model API
  - Layer interface with C-style polymorphism (vtable)
  - Dense layer, all activation layers as wrappers
  - Sequential container
  - Model compile/fit/predict/summary
  - Train/eval mode switching

Phase 5: Serialization + Data Pipeline
  - Binary model format (.axm) — v3 with buffers support
  - Tensor I/O format (.axt)
  - Save/load for all 14+ layer types including conv params
  - Serializes trainable params AND non-trainable buffers (running stats)
  - Tensor dataset, CSV dataset
  - Dataloader with batching and Fisher-Yates shuffling
  - Transforms: normalize, normalize_with, one_hot, minmax_scale

Phase 6: Convolutional Layers
  - Conv2D with im2col/col2im (stride, padding, bias)
  - MaxPool2D, AvgPool2D, GlobalAvgPool2D
  - Flatten layer
  - Full backward pass for all (autograd flows through entire CNN pipeline)

Phase 7: Normalization + Regularization
  - BatchNorm (2D and 4D, with Bessel's correction, running stats)
  - LayerNorm
  - Dropout (inverted scaling)
  - Gradient clipping (by value and by norm)
  - LR schedulers: step decay, exponential, cosine, warmup+cosine

Production Hardening:
  - Integer overflow protection in all shape calculations
  - Bounds checking on tensor element access (always on)
  - Model file parsing validation (14 specific checks)
  - Iterative DFS in autograd (no stack overflow)
  - Graph cleanup for zero memory leaks
  - Owned tensor tracking in grad_fn (saved_owned[], ctx_cleanup)
  - Contiguous-safe backward (ax_ensure_contiguous on all saved tensors)
  - IEEE 754 division by zero (returns infinity, not 0)
  - ASan + UBSan build mode
  - Compiler hardening flags (-fstack-protector-strong, _FORTIFY_SOURCE)
  - 18 test suites, all passing under sanitizers
  - Numerical gradient verification against finite differences
  - Serialization roundtrip verified for every layer type

================================================================================
6. CODING GUIDELINES
================================================================================

Style:
  - C11 standard
  - All public symbols prefixed with ax_
  - All macros/enums prefixed with AX_
  - Lowercase, succinct, formal comments
  - No AI-style dash separators (/* --- section --- */ is banned)
  - Human-readable code that doesn't look AI-generated
  - Allman brace style for functions, K&R for control flow is fine
  - No unnecessary abstractions — three similar lines > premature helper

Security (see SECURITY.md for full policy):
  - Every allocation checked for NULL
  - Integer overflow checked in shape calculations (safe_mul_i64)
  - Bounds checking on tensor access (always on, not just debug)
  - File parsing validates every field before use
  - No exit() in library code — return error codes
  - No printf of user-controlled format strings
  - grad_fn->saved_owned[] marks tensors the grad_fn must free
  - grad_fn->ctx_cleanup frees ctx if backward never ran
  - All backward functions null out self->ctx after freeing

Quality:
  - Every feature must have: forward, backward (with autograd), correct
    layer type enum, serialization support, tests
  - No half-baked features. Build less, build it right.
  - Numerical gradient verification for differentiable ops
  - Integration tests that prove training actually works
  - Serialization roundtrip tests for every layer type
  - ASan + UBSan must pass with zero errors before any commit
  - Examples must show zero memory leaks under ASan

Attribution:
  - No Co-Authored-By lines in commits
  - No AI/Claude/Anthropic mentions anywhere in the repo
  - settings.json has attribution set to empty strings

Embedded considerations:
  - Fixed-size arrays (AX_SEQ_MAX_LAYERS, AX_LAYER_MAX_PARAMS, etc.)
  - Arena allocator for temporary buffers
  - 64-byte alignment for SIMD readiness
  - No dynamic linking dependencies
  - Binary model format designed for microcontrollers (no protobuf/JSON)
  - In inference mode, sequential forward frees intermediates between layers


================================================================================
7. BUILD INSTRUCTIONS
================================================================================

Standard build:
  mkdir build && cd build
  cmake ..
  make -j$(nproc)
  ctest --output-on-failure

Sanitizer build (for development):
  cmake .. -DCMAKE_BUILD_TYPE=Debug -DAX_SANITIZE=ON
  make -j$(nproc)
  ctest --output-on-failure

The sanitizer build enables AddressSanitizer and UndefinedBehaviorSanitizer.
Tests suppress leak detection (test code intentionally doesn't clean up all
intermediates), but examples run with full leak detection.


================================================================================
8. HOOKS AND AUTOMATION
================================================================================

Two hooks are configured in .claude/settings.local.json (gitignored):

1. Security review hook: after every Edit/Write to .c/.h files, scans for
   unchecked allocations, dangerous functions, unchecked shape math.
   Injects findings into the conversation context.

2. Test hook: after every Edit/Write to source files, rebuilds the project
   and runs all tests. Blocks if any test fails.
